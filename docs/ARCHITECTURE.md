# Техническая документация KC97 Cockpit Launcher (v1.9)

## 1. Целевая платформа и архитектура

Лаунчер спроектирован специально для бюджетных и среднебюджетных китайских Android-ГУ (протестировано на **KTE KC97 / X20G_CJ01_KTE**, MediaTek MT6797 Helio X20, 4 ГБ ОЗУ, реальный **Android 8.0 Oreo API 26**, разрешение `2000×1200`).

Ключевой принцип проектирования — **нулевые зависимости и ноль WebView**:
- Весь UI строится программно на нативных Android `View` / `Canvas`.
- Отсутствие AndroidX/Gradle/WebView удерживает размер APK в пределах **~58 КБ**, а рабочее потребление RAM на уровне **28–36 МБ** (против 300–1000 МБ у штатных и сторонних лаунчеров).

## 3. Протокол OBD-II через `/dev/socket/goc_spp` (SD-968)

На магнитолах KTE с Bluetooth-модулем **SD-968** (`/dev/ttyMT3`, демон `/ksys/bin/sdsdk968`) системный сервис `com.android.bluetooth` отсутствует, а доступ к SPP-профилю открыт через локальный Unix-сокет:
- Путь сокета: `/dev/socket/goc_spp` (`srwxrwxrwx`, доступен обычному приложению без root).
- **Критическая деталь бинарного протокола `sdsdk968` (`sub_97c0` @ `0x0097e8`):** при `spp_handle == 0` демон проверяет длину первого пакета инструкцией `cmp r1, #0xc` (`len == 12`)! Необходимо отправить **строго 12 ASCII-байт MAC-адреса БЕЗ `\r\n`** (например, `"001DA50821EB"`) и выждать `~4.5 с` для установления RFCOMM-канала через `bt_spp_connect` (`0x18b9c`). Добавление `\r\n` (14 байт) приводит к пропуску вызова `bt_spp_connect` после перезагрузки, а отправка `AT#SP` в `/dev/goc_serial` ошибочно активирует профиль Apple iAP и перезапускает демон `sdsdk968`.
- Автоопределение MAC: лаунчер автоматически читает секцию `[PAIRSTLIST]` файла `/data/goc/bt_conf.ini` (`0777`) и находит сопряжённое устройство `OBDII`.
- После установления канала сокет работает как прозрачный последовательный порт к ELM327.

### Устойчивый цикл подключения к Honda ECU (ISO 9141-2)
1. Сброс адаптера: `ATZ` → `ATE0` → `ATL0` → `ATS0` → `ATSP0`.
2. Опрос напряжения `ATRV` (работает даже при выключенном зажигании / в `ACC`).
3. Рукопожатие с ЭБУ (`handshakeEcu`):
   - `ATPC` (закрыть зависшую сессию) → `ATSP0` → `0100` с полным дедлайном `12 с`.
   - Критично для `LocalSocket` на Android 8: таймаут чтения (`EAGAIN` / `"Try again"`) обрабатывается как продолжение ожидания до истечения `deadline`, чтобы 5-бодовая инициализация Honda (`BUS INIT: ...`, ~4.5–5 с) не обрывалась преждевременно.
4. При потере ЭБУ (`NO DATA` / `UNABLE` / `ERROR` при глушении двигателя) статус переходит в жёлтый (`connecting = true`), статистика сохраняется, и цикл периодически повторяет чистое рукопожатие до следующего включения зажигания.

### TCP-мост для Car Scanner (`127.0.0.1:35000`)
- Поток `OBD-TcpBridge` слушает `127.0.0.1:35000`.
- При подключении внешнего клиента (например, Car Scanner ELM OBD2) лаунчер сохраняет накопленный расход, временно освобождает `goc_spp`, пробрасывает байты `TCP ↔ goc_spp` в оба направления, а после отключения клиента автоматически возобновляет опрос телеметрии.

## 4. Расчёт расхода топлива (Speed-Density)

Для ЭБУ, не отдающих PID `0110` (MAF) и `015E` (Fuel Rate) — как на **Honda Stream RN3 (K20A, `0100 = 4100BE3EA801`)**, — используется физическая модель Speed-Density по PID `010B` (MAP, кПа), `010C` (RPM), `010F` (IAT, °C) и `010D` (скорость, км/ч):

$$\text{MAF}_{\text{est}}\text{ (г/с)} = \frac{\text{RPM} \cdot \text{MAP}_{\text{кПа}}}{T_{\text{IAT (K)}}} \cdot V_{\text{eng (л)}} \cdot \text{VE} \cdot 0.02904$$

$$\text{Расход (л/ч)} = \text{MAF}_{\text{est}} \cdot \frac{3600}{14.7 \cdot 745} \approx \text{MAF}_{\text{est}} \cdot 0.3287$$

- Коэффициент `0.02904` выведен из уравнения состояния идеального газа для 4-тактного двигателя: $\frac{1000 \cdot 28.97}{8.3145 \cdot 120000} \approx 0.029036$.
- Значение объёмного КПД по умолчанию: `DEFAULT_VE = 0.78` (калибровка под атмосферный Honda K20A 2.0L).
- **Отсечка ПХХ (торможение двигателем):** при `RPM > 1500`, `MAP ≤ 20 кПа` и `Speed > 20 км/ч` мгновенный расход принимается равным `0.0 л/ч`.
- **Персистентность:** `total_km` и `total_liters` сохраняются в `SharedPreferences` (`kc97_obd_stats`) каждые 15 секунд, при потере ЭБУ, в `onPause()` и `onDestroy()`.

## 5. Пороги индикации ОЖ и фильтрация скорости

### Температура антифриза (`0105`, °C = byte - 40)
- `< 50°C` — 🔵 Синий (`#38BDF8` / `#0D2842`)
- `50 .. 98°C` — 🟢 Зелёный (`#4ADE80` / `#0F2920`)
- `99 .. 106°C` — 🟡 Жёлтый (`#FDE047` / `#3B2A0A`)
- `≥ 107°C` — 🔴 Красный (`#FCA5A5` / `#4C0D19`)

### Защита спидометра от дрейфа GPS на стоянке
- **При активном ЭБУ (`obdEcuReady == true`):**
  - Если `RPM < 150` и `ecuSpeed == 0` → скорость строго `0`.
  - Если `ecuSpeed == 0` → дрейф GPS до `10 км/ч` игнорируется (`0`).
  - Если `ecuSpeed > 0` → используется точная скорость GPS (при `accuracy < 30 м`), иначе `ecuSpeed`.
- **Без ЭБУ (зажигание выключено / `ACC`):**
  - Выход из `0 км/ч` требует либо `≥ 10 км/ч` (`accuracy < 25 м`), либо **2 подряд** валидных замера `≥ 6 км/ч` (`≥ 9 км/ч` при плохой точности `> 25 м`).
  - Возврат в `0 км/ч` — при падении скорости `< 3 км/ч`.

## 6. Аппаратные интерфейсы KTE / KC97

| Сигнал | Источник в системе | Значения |
|---|---|---|
| Фары / габариты | `Settings.System` → `"Headlamp"` | `0` выкл, `1` вкл (запускает авто-ночной режим: яркость окна `0.28` + затемнение карты) |
| Ручной тормоз (реальный провод) | `/sys/devices/virtual/kte/kte_hand_brake/hand_brake_status` | `0` отпущен, `1` поднят |
| Задний ход | `Settings.System` → `"backcar_satus"` | `0` нет, `1` включён |
| Температура CPU | `/sys/class/thermal/thermal_zone1/temp` | миллиградусы °C |
| Bluetooth-музыка (`KteBluetooth`) | Broadcasts `com.kte.bluetooth_*` | `playPause`, `next`, `previous`, `playName`, `playStatus`, `btState`, `getName` |
